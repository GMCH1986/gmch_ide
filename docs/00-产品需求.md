## 1. 背景与目标

### 1.1 背景

团队需要一个**面向 Java 日常开发**的桌面 IDE：打开 Gradle 工程、编辑源码、编译、运行、查看输出，并能以安装包分发到 Windows / macOS / Linux。现有通用 IDE 能力过剩、启动与内存开销大，且难以深度定制；自研载体可以把「编辑 → 构建 → 运行」这条链路做短，并为后续接入自有诊断、AI 辅助预留空间。

### 1.2 v0.1.0 目标

打通最小可用闭环，并完成一次真实的发布验证：

> **装得上 → 打得开 → 改得动 → 编得过 → 跑得起来 → 看得见日志**

同时验证三项工程假设：

1. Electron 壳 + Java sidecar + Gradle 的进程链路在三平台都成立；
2. 打包产物（NSIS / DMG / AppImage）可以安装并正常启动；
3. 首次启动、编辑、构建的体验达到可演示水平。

### 1.3 成功标准

- 三个平台各产出一个可安装产物，安装后能完成场景 A（见 2.2）。
- 冷启动到可编辑 ≤ 2.5s；后端就绪 ≤ 5s；1MB 文件打开 ≤ 300ms。
- 连续编辑 10 分钟无输入卡顿、无内存持续增长。

## 2. 目标用户与场景

### 2.1 目标用户

- 需要频繁修改、编译、运行单个 Gradle 工程的 Java 开发者；
- 希望在轻量工具里完成「改一行 → 跑一下」的开发者；
- 后续会接入团队自有工具链（诊断、代码生成、AI）的内部团队。

### 2.2 核心场景

| 编号 | 场景 | 期望路径 |
| --- | --- | --- |
| A | 快速修改并运行 | 打开工程 → 点文件 → 改代码 → `Ctrl+S` → `F5` → 看输出 |
| B | 验证能否编译 | 改代码 → 编译 → 输出报错 → 回到代码定位 |
| C | 分发安装 | 下载对应平台安装包 → 安装 → 首次打开 → 打开工程 |

## 3. 版本范围

### 3.1 v0.1.0 范围内（In Scope）

- 单窗口、单工作区；
- 打开本地文件夹作为工作区（Gradle 工程）；
- 工作区文件列表（`.java` / `.gradle` / `.properties` / `.md` / `.kts`）；
- 代码编辑：Java 语法高亮、行号、括号匹配、代码折叠、搜索替换、多光标；
- 保存（`Ctrl+S`）与未保存标记；
- 编译（`gradlew compileJava`）与运行（`gradlew run`）；
- 流式输出面板：停止、清空、自动滚动、行数上限；
- 状态栏：工作区、当前文件、光标行列、构建状态、后端状态；
- 关闭前未保存确认；
- 窗口尺寸/位置记忆、单实例；
- 环境自检（JDK 版本、Gradle Wrapper）；
- 三平台安装包与发布验证清单。

### 3.2 明确不做（Out of Scope，留给后续版本）

| 能力 | 计划版本 |
| --- | --- |
| 多标签页、文件树折叠/新建/删除/重命名 | v0.2 |
| 自动更新、代码签名与公证 | v0.2 |
| LSP：补全、悬停、跳转、诊断、格式化 | v0.3 |
| 调试（断点、变量、调用栈） | v0.4 |
| Git 集成、内置终端 | v0.5 |
| 主题切换、多工作区、插件体系、账号/协同 | v1.0 前评估 |

## 4. 功能需求

> 约定：每条需求给出「描述 / 交互 / 验收标准」。验收标准必须可实测，不用「体验良好」这类描述。

### FR-01 启动与后端就绪

- **描述**：应用启动后立即显示主界面，Java 后端（sidecar）在后台启动。
- **交互**：后端未就绪时，状态栏显示「后端启动中…」，编辑器区域显示骨架而不是白屏；超过 30s 显示失败原因与「重试」按钮。
- **验收**：
  1. 双击应用后 ≤ 2.5s 出现主界面；
  2. 后端就绪 ≤ 5s，状态栏变为「就绪」；
  3. 删除 `resources/backend` 后启动，界面提示「后端未构建」并给出构建命令，不崩溃。

### FR-02 打开 / 恢复工作区

- **描述**：选择一个本地目录作为工作区，后端只在该目录内读写。
- **交互**：菜单「文件 → 打开文件夹」或 `Ctrl+O`；选择后写入 `userData/settings.json`；下次启动自动恢复。
- **验收**：
  1. 选择目录后文件列表在 1s 内刷新；
  2. 重启应用后自动恢复上次工作区；
  3. 上次目录被删除时，启动提示「工作区不存在」，可重新选择，不崩溃。

### FR-03 文件列表

- **描述**：递归展示工作区内可编辑文件。
- **交互**：左侧列表显示相对路径；当前文件高亮；点击打开。
- **验收**：
  1. 忽略 `build/`、`.gradle/`、`.git/`、`out/`、`node_modules/`；
  2. 按路径字典序排列；
  3. 1000 个文件以内列表渲染 ≤ 300ms。

### FR-04 代码编辑

- **描述**：基于 CodeMirror 6 的 Java 编辑器。
- **交互**：点击文件加载内容；光标行列实时更新；`Ctrl+F` 搜索。
- **验收**：
  1. 1MB 文件打开 ≤ 300ms；
  2. 连续输入 10 分钟无可感知卡顿（输入延迟 p95 ≤ 16ms）；
  3. 中文注释、UTF-8 文件读写不乱码。

### FR-05 保存

- **描述**：把编辑器内容写回磁盘。
- **交互**：`Ctrl+S` 或菜单「文件 → 保存」；成功后清除未保存标记。
- **验收**：
  1. 保存后磁盘内容与编辑器一致（含结尾换行）；
  2. 保存失败（只读/占用）时弹出错误提示，内容不丢失；
  3. 未保存标记在标题栏/状态栏可见。

### FR-06 编译

- **描述**：在工作区执行 `gradlew compileJava`。
- **交互**：`F7` 或菜单「构建 → 编译」；输出进入输出面板。
- **验收**：
  1. 输出逐行流式出现，不是结束后一次性输出；
  2. 退出码 0 显示「编译成功」，非 0 显示「编译失败」；
  3. 无 `gradlew` 时提示「工作区缺少 Gradle Wrapper」，不启动进程。

### FR-07 运行

- **描述**：在工作区执行 `gradlew run`。
- **交互**：`F5` 或菜单「构建 → 运行」；运行中可 `Shift+F5` 停止。
- **验收**：
  1. 输出流式显示；
  2. 停止后 2s 内进程树被清理（任务管理器中无残留 java 进程）；
  3. 同一时刻只允许一个构建/运行任务。

### FR-08 输出面板

- **描述**：展示构建/运行的标准输出与错误输出（已合并）。
- **交互**：自动滚动到底部；可手动上翻（上翻时暂停自动滚动）；「清空」按钮。
- **验收**：
  1. 最多保留 2000 行，超出丢弃最早的行；
  2. 运行中「运行」按钮禁用；
  3. 面板可折叠/展开（v0.1 至少可拖拽调整高度）。

### FR-09 状态栏

- **描述**：常驻显示关键上下文。
- **验收**：显示工作区名、当前文件相对路径、`Ln x, Col y`、运行状态（空闲/运行中/成功/失败）、后端状态。

### FR-10 退出保护

- **描述**：关闭窗口时保护未保存内容。
- **交互**：有未保存修改时拦截关闭，弹窗提供「保存并退出 / 放弃修改 / 取消」。
- **验收**：
  1. 选「取消」窗口保持打开；
  2. 选「保存并退出」写盘成功后退出；
  3. 保存失败时不退出并提示原因。

### FR-11 窗口与单实例

- **验收**：
  1. 记忆窗口尺寸、位置、最大化状态；
  2. 二次启动只聚焦已有窗口，不新开实例。

### FR-12 环境自检

- **描述**：启动时检测运行构建所需的环境。
- **验收**：
  1. JDK 版本 < 17 时在状态栏提示「需要 JDK 17+（推荐 21）」；
  2. 工作区无 `gradlew` 时，编译/运行前给出明确提示；
  3. 不因环境缺失导致应用崩溃。

## 5. 非功能需求

| 编号 | 类别 | 要求 |
| --- | --- | --- |
| NFR-01 | 性能 | 冷启动 ≤ 2.5s；后端就绪 ≤ 5s；输入延迟 p95 ≤ 16ms；1MB 文件打开 ≤ 300ms；内存 ≤ 400MB（含 JVM） |
| NFR-02 | 可靠性 | 后端崩溃不拖垮界面，可一键重启；构建进程可终止；退出无残留子进程 |
| NFR-03 | 安全 | `contextIsolation: true`、`sandbox: true`、`nodeIntegration: false`；CSP 限制 `connect-src`；后端仅绑定 `127.0.0.1`，随机端口 + 随机 token；工作区路径越界一律 400 |
| NFR-04 | 兼容 | Windows 10+ x64；macOS 12+（Intel / Apple Silicon）；Ubuntu 22.04+ x64 |
| NFR-05 | 可维护 | TypeScript strict；主进程/渲染进程双 tsconfig；关键决策写入 `docs/01-技术方案.md` |

## 9. 错误与边界

| 场景 | 期望行为 |
| --- | --- |
| JDK 缺失 / 版本过低 | 状态栏红色提示 + 点击查看指引；不阻止编辑 |
| `gradlew` 缺失 | 编译/运行前提示，不启动进程 |
| 工作区被删除 | 文件列表清空并提示重新选择 |
| 构建超时（10 分钟） | 自动终止并提示 |
| 输出超过 2000 行 | 丢弃最早的行 |
| 端口被占用 | 重新选择端口（最多 3 次） |
| 后端启动失败 | 显示 stderr 末尾 20 行 + 重试按钮 |

## 11. 风险与开放问题

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| `jlink` 裁剪缺少 Spring Boot 反射所需模块 | 后端启动失败 | 建立最小模块清单并加冒烟用例；失败则回退完整 JRE |
| Gradle 首次构建下载依赖慢 | 首跑体验差 | 输出面板显示进度；文档提示预热的 `~/.gradle` |
| 未签名安装包被拦截 | 安装转化率低 | v0.2 引入签名/公证 |
| 工作区含大量文件 | 列表卡顿 | 限制遍历深度与数量，超出提示 |
| 用户 JDK 与构建 JDK 不一致 | 编译行为差异 | 状态栏显示检测到的 JDK 版本 |

**开放问题（需产品确认）**：

1. 产品正式名称与品牌标识（当前暂用 `GMCH IDE` / `com.gmch.ide`）；
2. v0.1.0 是否必须支持 Apple Silicon 原生（当前计划 universal）；
3. 是否需要在 v0.1.0 就内置 JDK（当前计划依赖用户环境）。
