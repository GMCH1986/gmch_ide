## 1. 目录职责

| 目录 | 只放什么 | 禁止什么 |
| --- | --- | --- |
| `src/main` | 窗口、菜单、单实例、sidecar 生命周期、设置持久化 | 业务逻辑（文件解析、构建） |
| `src/preload` | `contextBridge` 白名单与类型声明 | 任何业务计算 |
| `src/shared` | 跨进程纯类型 | 运行时依赖、`import 'electron'` |
| `src/renderer` | UI、编辑器、HTTP/SSE 客户端 | `import 'electron'`、Node API |
| `backend` | 文件 API、Gradle 执行、环境探测 | 桌面/窗口相关逻辑 |
| `scripts` | 构建、环境自检、发布校验 | 运行时依赖 |
| `docs` | 需求、方案、规范、验证、路线图 | 临时笔记 |

## 2. 命名约定

| 对象 | 规则 | 示例 |
| --- | --- | --- |
| IPC 通道 | `域:动作`（小写 + 冒号） | `workspace:pick`、`app:get-info` |
| 主进程事件 | `域:事件` | `menu:action`、`app:close-request` |
| Vue 组件 | PascalCase，按领域分目录 | `components/CodeEditor.vue` |
| Composable / Store | `useXxx.ts` / `xxx.ts` | `stores/ide.ts` |
| 工具函数 | kebab-case | `build-backend.mjs` |
| Java 包 | `com.gmch.ide.<层>` | `com.gmch.ide.api` |
| Java 类 | PascalCase，后缀表意 | `GradleRunner`、`TokenFilter` |
| CSS 类 | kebab-case，布局前缀 | `ide-sidebar`、`editor-host` |

## 3. 分支与提交

### 3.1 分支

- `main`：可发布分支，任何提交必须能通过 `npm run typecheck` 与冒烟主路径；
- `feat/<主题>`、`fix/<主题>`：开发分支，合入前 squash。

### 3.2 提交信息

采用 Conventional Commits，描述用中文：

```
feat(editor): 支持 Ctrl+S 保存并标记脏状态
fix(backend): 停止构建时清理 Gradle 子进程树
chore(release): v0.1.0
```

常用类型：`feat` / `fix` / `refactor` / `docs` / `chore` / `test` / `build`。

### 3.3 版本

- 语义化版本 `MAJOR.MINOR.PATCH`，当前 `0.x` 阶段：`MINOR` 用于功能，`PATCH` 用于修复；
- 发版必须打 tag：`v0.1.0`；
- 版本号唯一来源是 `package.json` 的 `version`，构建脚本与后端 `/api/health` 均读取/对齐它。

## 4. 质量门槛

### 4.1 提交前（本地）

```bash
npm run doctor       # 环境自检：Node / JDK / Gradle Wrapper
npm run typecheck    # 主进程 + 渲染进程双 tsconfig
npm run format       # Prettier 写入
```

### 4.2 合入 `main` 前

1. `npm run typecheck` 通过；
2. `npm run build` 通过；
3. `npm run dev` 下主路径手工验证（打开工作区 → 编辑 → 保存 → 编译 → 运行）；
4. 涉及 IPC / 跨进程数据结构变更时，同步更新 `docs/01-技术方案.md` 与 `src/shared/types.ts`。

### 4.3 发版前

执行 `docs/03-发布验证.md` 的 S1–S10，并留档结果。

### 4.4 后续补充（v0.2）

- ESLint（`typescript-eslint` + `eslint-plugin-vue`）；
- Vitest：纯函数（路径校验、输出裁剪、Gradle 命令拼装）；
- Playwright：Electron e2e（启动、打开工作区、保存）。

## 5. 代码风格

- Prettier：无分号、单引号、2 空格、`printWidth: 100`、无尾逗号；
- TypeScript：`strict: true`，禁止 `any`（确需时写明理由），禁止 `@ts-ignore`；
- 渲染进程不得直接操作编辑器 DOM 之外的状态；编辑器实例必须 `markRaw` / 非响应式持有；
- 中文注释用于「为什么」，不复述「是什么」；
- 日志只用 `console.error` / `console.warn`，文案简短英文；界面文案中文。

## 6. 文档规则

1. **文档先行**：新增功能先在 `docs/` 补需求或方案，再改代码；
2. 涉及 IPC 契约、数据结构、持久化格式的变更，必须单独成文或在 `01-技术方案.md` 增加 ADR 条目；
3. 已知限制集中记录在 `01-技术方案.md` 第 8 节，不在代码注释里散落；
4. 发布验证结果按 `03-发布验证.md` 模板记录，随 tag 归档。

## 7. 评审检查清单

- [ ] 新增 IPC 是否三处同步（main / preload / `shared/types.ts`）？
- [ ] 是否引入了渲染进程的 Node 能力或 `import 'electron'`？
- [ ] 文件路径是否经过工作区越界校验？
- [ ] 长任务是否会阻塞 UI 或主进程？
- [ ] 失败路径是否有可见提示（而不是静默）？
- [ ] 是否更新了对应文档？
