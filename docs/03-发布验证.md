## 1. 前置条件

| 项 | 要求 | 检查命令 |
| --- | --- | --- |
| Node.js | ≥ 22 | `node -v` |
| JDK | 21（最低 17） | `java -version` |
| Gradle | 由工作区自带 Wrapper，无需全局安装 | 工作区存在 `gradlew` / `gradlew.bat` |
| 系统 | Windows 10+ / macOS 12+ / Ubuntu 22.04+ | — |

> 首次构建前执行 `npm run doctor`，缺项会直接列出。

## 2. 构建

### 2.1 一次性准备

```bash
npm install
npm run doctor
```

> 仓库已提交 `backend/` 与 `examples/hello-java/` 的 Gradle Wrapper，无需本机安装 Gradle。
> 如需重新生成：`cd backend && gradle wrapper --gradle-version 8.12`。

### 2.2 三平台

```bash
# Windows
npm run build:win

# macOS（建议在 macOS 上执行，产物为 dmg + zip）
npm run build:mac

# Linux
npm run build:linux
```

流水线：`typecheck → electron-vite build → bootJar → jlink → electron-builder`。

### 2.3 冒烟用工作区

仓库内置最小 Gradle 工程 `examples/hello-java`（已带 Gradle Wrapper），S2 / S5 / S7 直接选择该目录即可。

### 2.4 产物清单

| 平台 | 文件 | 预期位置 |
| --- | --- | --- |
| Windows | `gmch-ide-0.1.0-setup.exe`（NSIS） | `dist/` |
| Windows | `GMCH IDE-0.1.0-win.zip`（免安装） | `dist/` |
| macOS | `gmch-ide-0.1.0-universal.dmg`、`gmch-ide-0.1.0-universal.zip` | `dist/` |
| Linux | `gmch-ide-0.1.0.AppImage`、`gmch-ide_0.1.0_amd64.deb` | `dist/` |

> `nsis.runAfterFinish: false`：安装完成后不自动启动，避免「装完就在运行」导致再次安装时提示无法关闭。
> 安装/卸载前如果任务管理器里仍有 `GMCH IDE.exe`，先结束进程；也可以直接用 `win.zip` 免安装包。

校验命令：`npm run verify:release`（检查产物存在、版本号一致、体积在预期区间）。

### 2.5 自动化验证

| 命令 | 覆盖内容 | 依赖 |
| --- | --- | --- |
| `npm run typecheck` | 主进程 + 渲染进程类型 | Node |
| `npm run build` | electron-vite 三段构建 | Node |
| `npm run backend:build` | bootJar + jlink 裁剪 | JDK 21 |
| `npm run smoke:backend` | 健康检查、token 鉴权、文件 API、SSE 编译 | JDK 21 + Gradle |

`smoke:backend` 会启动 jlink 运行时并执行 `examples/hello-java` 的 `compileJava`，退出码非 0 即失败。

## 3. 冒烟用例

> 每条用例记录：结果（通过/失败）、平台、备注。失败必须附日志或截图路径。

| 编号 | 用例 | 步骤 | 预期 |
| --- | --- | --- | --- |
| S1 | 安装并启动 | 运行安装包 → 启动 | 5s 内出现主界面，状态栏显示「就绪」 |
| S2 | 打开工作区 | 菜单「打开文件夹」→ 选择含 `gradlew` 的工程 | 1s 内列出文件，首个文件自动打开 |
| S3 | 编辑与脏标记 | 修改代码 | 状态栏出现未保存标记，输入无卡顿 |
| S4 | 保存 | `Ctrl/Cmd + S` | 标记消失；用外部编辑器确认磁盘内容一致 |
| S5 | 编译成功 | `F7` | 输出流式刷新，结束显示「编译成功」 |
| S6 | 编译失败 | 故意写错语法 → `F7` | 显示 `error:` 行，状态为失败 |
| S7 | 运行 | `F5` | 输出显示程序输出，状态为成功/失败 |
| S8 | 停止 | 运行一个长任务 → `Shift+F5` | 2s 内停止，无残留 java 进程 |
| S9 | 退出保护 | 修改不保存 → 关闭窗口 | 弹窗询问；取消后窗口仍在；保存后退出 |
| S10 | 重启恢复 | 打开工作区后退出 → 重启 | 自动恢复工作区与窗口尺寸 |
| S11 | 新建工程 | 菜单「新建工程」→ 默认 `hello-java` / `GMCHProjects` → 创建 | 自动打开 `Main.java`；`F5` 输出 `Hello, GMCH IDE!` |

### 3.1 安装 / 卸载 / 覆盖安装

| 平台 | 安装 | 卸载 | 覆盖安装 |
| --- | --- | --- | --- |
| Windows | 双击 exe，允许自定义目录 | 设置 → 应用 → 卸载 | 直接运行新安装包 |
| macOS | 打开 dmg，拖入 Applications | 移到废纸篓 | 覆盖 Applications 内应用 |
| Linux | AppImage 直接运行；deb 用 `dpkg -i` | `dpkg -r` | 安装新包 |

验证点：卸载后 `%APPDATA%/gmch-ide`、`~/Library/Application Support/gmch-ide`、`~/.config/gmch-ide` 是否保留（v0.1 保留配置，属预期）。

## 4. 发布流程

1. 确认 `package.json` 版本号；
2. 执行 `docs/03` 冒烟清单；
3. 提交 `chore(release): vX.Y.Z`；
4. 打 tag：`git tag vX.Y.Z && git push origin vX.Y.Z`；
5. CI 三平台构建并上传产物（`.github/workflows/release.yml`）；
6. 在 GitHub Release 附上产物与「本版限制」；
7. 归档冒烟记录到 Release 说明。

## 6. 回滚

- 保留上一个可用版本的安装包与 tag；
- 发布后 24h 内出现 P0（无法启动、数据丢失）时，删除 Release 并回退 tag；
- 因 v0.1 无自动更新，回滚只需重新分发旧安装包。
